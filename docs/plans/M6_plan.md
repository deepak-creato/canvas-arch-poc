# M6 — Garbage collection, recovery and reconciliation (POC-031 to POC-036)

## Context

M1 to M5 are done. `gc-worker` is still the compose stub. Exit demo: short grace periods (minutes), discard a draft, run GC, only unreferenced media is deleted; assets shared with other drafts or publications stay intact.
Existing pieces GC builds on: `recalcRetention` (`services/shared/refs.ts`) sets `ORPHANED` + `orphaned_at` when the last reference goes; `lockReferenceable` already rejects new references to `DELETING`/`DELETED` (`422 ASSET_NOT_REFERENCEABLE`); `job-repo.ts` has leases; light-worker consumes S3 "Object Created" events.

## Decisions (stated, not asked; reverse any you dislike)

- **One service, `gc-worker`.** Real NestJS-free Node service like `mock-transcoder` (`services/gc-worker`). Steps are plain functions `(pool, s3, opts) => summary` in `src/`, so tests call them directly. HTTP on `127.0.0.1:3104`: `GET /healthz`, `POST /run[?step=]` (one GC cycle or one step), `GET /ops/jobs`, `GET /ops/dlq`, `POST /ops/redrive`, `POST /ops/reconcile`. Make targets wrap them (`make gc-run`).
- **Schedule.** `GC_INTERVAL_SECONDS` runs a cycle on a timer; `0` disables it. Compose default is `0` (manual `make gc-run`) so integration tests are not racing a background sweep. A cycle takes a Postgres advisory lock, so two gc-workers never run at once.
- **Cycle order** (plan 7.4): reconcile missed events, expire uploads, purge discarded drafts, prune revisions, mark unattached, sweep (delete), reap stuck jobs. Each step is idempotent and bounded by `GC_BATCH_SIZE`.
- **Grace periods are config, all seconds** (`services/shared/config.ts`, test and demo values in `.env.example`): `GC_UPLOAD_EXPIRY_GRACE_SECONDS`, `GC_UNATTACHED_GRACE_SECONDS`, `GC_ORPHAN_GRACE_SECONDS`, `GC_REVISION_KEEP_LAST`, `GC_REVISION_MIN_AGE_SECONDS`, `GC_JOB_STALE_SECONDS`, `GC_RECONCILE_AFTER_SECONDS`, `GC_STRAY_GRACE_SECONDS`, `DRAFT_PURGE_GRACE_SECONDS` (replaces days; default `days * 86400`). Step functions take an options object defaulting to config; tests pass `0` or large values and an `ownerId` scope so they never touch other tests' rows.
- **Lock order** everywhere: draft row, then asset rows in id order (same as save). GC claims with `FOR UPDATE SKIP LOCKED`, so a row held by a save is skipped, never waited on.
- **POC-031.** `PENDING_UPLOAD` past `upload_expires_at` + grace -> `EXPIRED`. `UNATTACHED` assets that are `VALIDATED`/`REJECTED`/`EXPIRED`, have no reference and have been untouched for the unattached grace -> `ORPHANED` with `orphaned_at = now()`. The orphan grace then applies on top, so objects are never deleted by this step.
- **POC-032.** Purge: `DISCARDED` drafts with `purge_after <= now()` -> revisions deleted (cascade releases `media_reference`), draft `PURGED` (row stays as tombstone), `recalcRetention` on the released assets. Prune: for `ACTIVE` drafts, delete revisions that are not head, not pinned, not in the newest `GC_REVISION_KEEP_LAST`, and older than `GC_REVISION_MIN_AGE_SECONDS`. Published or pinned snapshots, and any revision a publication points to, are never pruned. A frozen draft (`PUBLISHING`/`PUBLISHED`) is not pruned.
- **POC-033.** Migration 0008 adds `media_asset.deleted_at`, `delete_attempts`, `delete_error`. Sweep, per asset in its own transaction: lock row, require `ORPHANED` and `orphaned_at` older than grace, re-check zero `media_reference` and zero `publication_asset`, no active job (POC-034), then `ORPHANED -> DELETING`, commit. Then delete objects outside the lock: original, every `media_rendition` key, and everything under `derived/{id}/` and `final/{id}/`. On success: `DELETED`, `deleted_at`, rendition rows removed (tombstone stays on the asset). On partial failure: stay `DELETING`, record `delete_error`, retried by later runs. `DELETING` assets cannot gain references, so the retry needs no new check. The light-worker acks messages for `DELETING`/`DELETED` assets.
- **POC-034.** "Active job" = `RUNNING` with a live lease, or `QUEUED`/`FAILED` with attempts left and updated within `GC_JOB_STALE_SECONDS` (so a lost message cannot block GC forever). Concurrent save/restore: the save holds the asset row lock, GC skips it; the save's `recalcRetention` flips the asset back to `REFERENCED`. Tests hold a transaction open to force both interleavings.
- **POC-035.** Reaper: `RUNNING` with an expired lease -> `FAILED` with `available_at = now()` (or `FAILED_PERMANENT` when attempts are used up), error `LEASE_EXPIRED`. Requeue: light-processing jobs that are `FAILED` with attempts left, or stale `QUEUED`, get a synthetic S3 "Object Created" event on the source queue (same message the real event would be). Redrive: `GET /ops/dlq` peeks DLQ depth and messages; `POST /ops/redrive` moves DLQ messages back to the source queue (receive/send/delete, no `StartMessageMoveTask` dependency) and resets the matching `FAILED_PERMANENT` jobs to `QUEUED` with attempts 0. `GET /ops/jobs?status=` lists failed and stuck jobs with errors and attempts. `final-transcode` jobs are not requeued here: their messages carry Step Functions tokens, `POST /v1/publications/{id}/retry` owns them.
- **POC-036.** Reconcile: `PENDING_UPLOAD` older than `GC_RECONCILE_AFTER_SECONDS` whose object exists (missed event) is confirmed through `confirmUpload` (new `ignoreExpiry` option while inside the expiry grace) and gets a synthetic event; size/type mismatch -> `REJECTED`. Drift report: `VALIDATED` asset with missing original -> reported `MISSING_ORIGINAL` (no auto-fix); `READY` rendition with missing object -> `FAILED` + `OBJECT_MISSING`. Stray objects: scan `staging/`, `derived/`, `final/`; an object is stray when no asset owns it, or its asset is `DELETED`. Strays are reported always and deleted only when older than `GC_STRAY_GRACE_SECONDS`, `dry_run` is off, and a fresh DB check still finds no owner.
